# 协议转换项目目录与函数说明

本文档基于 `newB` 目录中的三个 Qt/C++ 项目整理：

- `newB/`：`S0_1 -> W304`、`S106 -> W204` 协议转换项目
- `newB/newC/`：`W304 -> ICD304` 协议转换项目
- `newB/newD/`：与 `newC` 基本同构的另一个 `W304 -> ICD304` 变体项目

这些项目都属于同一类“协议转换网关/报文转码工具”，目录结构和代码组织方式高度相似。

---

## 1. 一个这类项目目录通常包含哪些文件

一个完整的此类项目，通常由下面几类文件组成：

1. **工程入口文件**
   - `main.cpp`
   - `peach.pro`
   - `config.xml`

2. **运行时调度与网络收发文件**
   - `messageconvert.h`
   - `messageconvert.cpp`

3. **协议数据结构定义文件**
   - `*_def.h`

4. **协议编解码文件**
   - `codec.h`
   - `codec.cpp`

5. **协议映射文件**
   - `xxx_to_yyy.h`
   - `xxx_to_yyy.cpp`

6. **编排文件**
   - `to_code_Choreography.h`
   - `to_code_Choreography.cpp`

7. **开发环境文件**
   - `peach.pro.user`
   - `build-.../`

8. **说明文档或接口文档**
   - `*.doc`

## 2. 目录级说明

### 2.1 `newB/`

主项目目录，负责：

- 监听 UDP 报文
- 识别并缓存源消息
- 按编排规则检查时序和有效期
- 调用映射函数完成协议转换
- 将目标报文重新编码并发送出去

该目录中的转换链是：

- `S0_1 -> W304`
- `S106 -> W204`

### 2.2 `newB/newC/`

派生项目目录，负责：

- 接收 `W304`
- 转换为 `ICD304`
- 编码并发送 `ICD304`

### 2.3 `newB/newD/`

与 `newC` 基本同构，也是：

- 接收 `W304`
- 转换为 `ICD304`
- 编码并发送 `ICD304`

可以把 `newC` 和 `newD` 看成两个平行版本，通常差别会体现在协议定义、接口文档或后续业务字段映射上。

## 3. `newB/` 根项目文件说明

### 3.1 `main.cpp`

**作用：**

- 程序入口
- 读取运行配置 `config.xml`
- 解析收发端口、IP、网络类型
- 启动 `messageConvert`

**函数说明：**

- `readMessageXML(QString path, QVector<std::shared_ptr<messageConvert::NetInfo>> &netlist)`
  - 读取 XML 配置文件
  - 把每个 `<Item>` 节点解析成一个 `NetInfo`
  - 提取字段：`ip`、`port`、`type`、`recv`、`feedBackPort`、`name`
  - 供后续网络监听和发送初始化使用

- `main(int argc, char* argv[])`
  - Qt 程序入口
  - 获取程序所在目录下的 `config.xml`
  - 调用 `readMessageXML`
  - 构造 `messageConvert`
  - 调用 `start()` 启动整个转换流程

---

### 3.2 `config.xml`

**作用：**

- 运行配置文件
- 定义接收端口与发送端口
- 说明哪些端口用于接收，哪些用于发送

**包含信息：**

- IP 地址
- 端口号
- 网络类型（如 UDP）
- `recv=1/0`：表示该条目是接收端还是发送端
- 反馈端口

这是运行时唯一外部网络配置来源。

---

### 3.3 `messageconvert.h`

**作用：**

- 定义运行时核心类 `messageConvert`
- 定义网络配置结构、缓存结构和外部接口

**类与结构说明：**

- `messageConvert`
  - 整个项目的运行时控制中心

- `NetInfo`
  - 描述一个网络端点
  - 包含：名称、IP、端口、反馈端口、网络类型、是否接收

- `msgDataInfo`
  - 描述一条缓存中的消息数据
  - 包含：原始数据、时间戳列表、来源名、IP、端口、状态、接收次数

**函数说明：**

- `messageConvert(QObject* parent = nullptr)`
  - 构造函数

- `showMessage(QString msg)`
  - 信号，预留给界面或日志输出

- `readPendingDatagrams(...)`
  - 接收并封装收到的网络报文

- `onCheckDataTimer()`
  - 定时检查缓存消息是否过期

- `pushData(...)`
  - 将收到的报文压入缓存

- `getData(...)`
  - 从缓存中按消息名、周期、次数取出可参与转换的数据

- `checkData(...)`
  - 检查缓存中某类目标消息是否超过有效期

- `msgConvertThread()`
  - 转换主循环线程

- `msgSendThread()`
  - 预留发送线程接口，当前代码中未实现主要逻辑

- `onSendMessage(QByteArray msg)`
  - 把编码后的目标报文发往发送端

- `S0_1dataPro()`
  - 处理 `S0_1` 源消息并转换为 `W304`

- `S106dataPro()`
  - 处理 `S106` 源消息并转换为 `W204`

- `start(...)`
  - 初始化 UDP 收发和后台转换线程

- `stop()`
  - 停止收发与定时器，释放资源

### 3.4 `messageconvert.cpp`

**作用：**

- `messageConvert` 的具体实现文件
- 负责运行时收包、缓存、调度、转换和发包

**函数说明：**

- `start(...)`
  - 根据 `NetInfo` 列表创建接收 socket 和发送 socket
  - 为每个接收 socket 绑定 `readyRead`
  - 启动转换线程
  - 启动缓存有效性检查定时器

- `onCheckDataTimer()`
  - 定时查询编排文件里的目标消息有效时间
  - 例如检查 `W30_4`、`W20_4` 是否超时

- `stop()`
  - 停止转换线程和定时器
  - 关闭所有 socket

- `onSendMessage(QByteArray msg)`
  - 遍历发送端列表，把目标报文广播/发送到指定地址

- `readPendingDatagrams(...)`
  - 从 socket 收到原始 UDP 数据后封装成 `msgDataInfo`
  - 记录来源、端口、时间戳、原始二进制
  - 再调用 `pushData`

- `pushData(...)`
  - 把消息存入缓存队列
  - 如果同名消息已存在，则比较内容，决定覆盖还是增加计数

- `checkData(QString name, int time)`
  - 检查缓存消息距离最近接收时间是否超过阈值
  - 超时则删除缓存，避免旧数据继续参与转换

- `getData(...)`
  - 从缓存中挑出满足：
    - 名称匹配
    - 计数满足
    - 时间间隔满足
    - 当前处理阶段未消费过
    的消息

- `S0_1dataPro()`
  - 从缓存中查找 `S0_1`
  - 调用 `decodeMsg(..., S0_1&)` 解码
  - 调用 `checkObjMaps(..., S0_1&)` 做约束校验与应答处理
  - 根据编排规则检查时序
  - 调用 `convert_s0_1_to_w304()` 完成字段映射
  - 调用 `encodeMsg(..., W304&)` 编码成目标报文
  - 根据目标状态决定直接发送还是暂存

- `S106dataPro()`
  - 与 `S0_1dataPro()` 逻辑相同
  - 区别在于源消息为 `S106`，目标消息为 `W204`

- `msgConvertThread()`
  - 后台循环
  - 周期性执行：
    - `S0_1dataPro()`
    - `S106dataPro()`

### 3.6 `codec.cpp`

**作用：**

- 整个项目最核心的协议编解码实现文件
- 把 XML 协议描述落成具体的位级读写逻辑

可以把这个文件理解成由四层内容组成：

#### A. 通用位操作函数

- `readBits(...)`
  - 按大端读取若干位

- `checkPosition(...)`
  - 检查当前读取位置是否越界

- `readBitsLE(...)`
  - 按小端读取若干位

- `appendBits(...)`
  - 向 `QByteArray` 追加指定长度的位

- `readBits_d(...)`
  - 读取浮点/双精度类位段

- `readBitsLE_d(...)`
  - 按小端读取浮点类位段

- `appendBits_d(...)`
  - 向字节流追加浮点位段

#### B. 每个协议类型的“分段读函数”

这类函数负责按协议段结构，把原始比特流读入对象字段。  
命名上通常是：

- `readOrigin(...)`
  - 读取基础段/原始段

- `readProlong(...)`
  - 读取扩展段

- `readContinueN(...)`
  - 读取第 N 个可选连续段、分支段或附加段

- `readW304(...)` / `readS0_1(...)` / `readW204(...)` / `readS106(...)`
  - 根据消息中的 key/控制位选择调用哪些分段读函数

#### C. 每个协议类型的“编码辅助函数”

这类函数负责把对象重新写回到二进制：

- `writeOrigin(...)`
  - 写基础段

- `writeProlong(...)`
  - 写扩展段

- `writeContinueN(...)`
  - 写第 N 个分支/连续段

- `writeSeq_N(...)`
  - 按协议规定的编码顺序组包

#### D. 每个协议类型的“规则与校验函数”

这类函数通常是由 XML 中的约束、分支、默认值规则生成的：

- `checkXXXSeqNum(...)`
  - 检查解码后的序列/编码序列是否合法

- `checkEncodeSeqNumber(...)`
  - 生成编码时使用的序列号或序列串

- `checkAtom_X(...)`
  - 检查单条原子约束

- `setAtom_X(...)`
  - 按默认值或规则修正原子约束

- `checkConstraint_X(...)`
  - 检查一组组合约束

- `setConstraint_X(...)`
  - 修正组合约束

- `checkVerify_X(...)`
  - 检查某个编码/字段条件是否满足

- `setVerify_X(...)`
  - 根据验证规则写入附加数据

- `VerifyField(...)`
  - 汇总执行字段约束校验

- `updateFieldValue(...)`
  - 统一给默认值字段、推导字段赋值

- `updateGroupFlag(...)`
  - 根据循环组和分支开关更新组状态

- `checkObjMaps(...)`
  - 对一个完整消息对象做规则检查，并在需要时产生应答消息

- `decodeMsg(...)`
  - 完整解码入口

- `encodeMsg(...)`
  - 完整编码入口

#### E. 本文件中 4 套协议实现

本文件实际包含 4 套编解码实现：

- `W304` 一套
- `S0_1` 一套
- `W204` 一套
- `S106` 一套

每一套都遵循同样的结构：

- 读段函数
- 序列检查
- 条件检查
- 编码写段函数
- `decodeMsg`
- `encodeMsg`
- `checkObjMaps`

也就是说，这个文件本质上是“多个协议的自动生成编解码器集合”。

## 5. 这类项目中各文件之间的协作关系

可以按下面的顺序理解整个系统：

1. `config.xml`
   - 决定从哪接收、往哪发送

2. `main.cpp`
   - 读取配置并启动程序

3. `messageconvert.cpp`
   - 负责收包、缓存、调度、转换和发包

4. `codec.cpp`
   - 负责把原始报文解码成对象，再把对象编码回报文

5. `*_def.h`
   - 提供协议对象的数据结构

6. `xxx_to_yyy.cpp`
   - 负责源协议对象到目标协议对象的字段映射

7. `to_code_Choreography.cpp`
   - 决定转换链路、时序约束和状态控制

---

## 6. 总结：一个这样的项目本质上由三层组成

### 第一层：协议层

- `*_def.h`
- `codec.h`
- `codec.cpp`

作用：

- 定义报文长什么样
- 定义怎么解码、怎么编码、怎么校验

### 第二层：映射层

- `xxx_to_yyy.h`
- `xxx_to_yyy.cpp`

作用：

- 定义源协议字段如何映射为目标协议字段

### 第三层：运行与编排层

- `main.cpp`
- `messageconvert.h`
- `messageconvert.cpp`
- `config.xml`
- `to_code_Choreography.h`
- `to_code_Choreography.cpp`

作用：

- 定义收发流程、调度顺序、时间关系、发送策略

---

## 7. 如果后续要继续扩展一个新项目，一般只需要新增哪些文件

如果新增一种协议转换链，通常需要补齐：

1. 新协议的数据结构文件
   - `new_proto_def.h`

2. 新协议编解码支持
   - 修改或生成 `codec.h/.cpp`

3. 新映射函数
   - `src_to_dst.h`
   - `src_to_dst.cpp`

4. 新编排规则
   - 修改 `to_code_Choreography.cpp`

5. 如需独立工程，再复制：
   - `main.cpp`
   - `messageconvert.h/.cpp`
   - `config.xml`
   - `peach.pro`
